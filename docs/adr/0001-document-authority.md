# 🧭 ADR-0001：分离现行契约、任务状态与历史证据

- 状态：Accepted。
- 日期：2026-11-23。
- 决策依据：用户已授权按前轮建议拆分设计文档与源码。
- 范围：文档所有权；不改变科学算法、功能语义或发布授权。

## 🎯 背景

阶段总文档混合设计、当前状态、完整实施流水和发布结果。不同位置重复记录“当前版本”与经验，导致历史指令易被误读为现行要求。继续以阶段号追加总文档会扩大每次接手的阅读成本。

## ⚖️ 备选

1. 继续追加一个总文件：链接简单，但状态冲突与检索噪声持续增长。
2. 只按长度切成若干文件：体积变小，信息职责仍混杂。
3. 按信息用途建立权威入口，并保留可追溯归档：需要迁移及链接检查，后续维护明确。

## ✅ 决定

采用方案3。AGENTS只保留工程红线和导航；现行架构/接口随代码更新；当前状态覆盖更新；一张任务卡记录一项工作；历史流水与原始证据分别归档。经验集中到EXPERIENCE，跨项目操作方法才进入skill。

公开仓库只包含可分享的架构和ADR；内部状态、业务样本路径、运行日志留在外部工作区。兼容入口保留旧文件名和锚点；原始字节备份与迁移清单用于确认无丢失。Changelog记录最终成果摘要，不承担执行日志。

## 📦 后果与约束

维护者按问题读取少量文档，但必须及时更新权威位置和链接。新路径不等于已建立版本控制；工作区外部文档仍需独立备份/私有版本管理，不能误认为产品Git已跟踪。

迁移仅调整信息组织，旧科学结论没有充分证据时标注历史/待核验，不机械升级为现行支持承诺。历史验收次数、全量测试流程和授权不延续到新任务。

## 🔄 复审条件

团队增加、内部文档进入私有仓库，或公开/私有边界改变时新增ADR。验证要求为链接可达、原文可追溯、状态唯一；不因此运行产品回归。
