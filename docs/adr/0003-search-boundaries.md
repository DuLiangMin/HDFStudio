# 🔎 ADR-0003：分开文件名查找与当前文件变量查找

- 状态：Accepted。
- 日期：2026-11-23。
- 关联需求：用户批准两个查找入口并授权设计、编码；实现状态由内部SEARCH-001任务记录。
- 替代关系：无；遵循ADR-0002的应用/视图边界。
- 澄清修订：2026-11-23，经用户要求审核；保留Accepted及原有两个检索范围，不改变采用理由。本次补清接口、资源和验证边界；不是一次新功能验收。

## 🎯 背景与约束

科研人员既需要按名称从目录找到文件，也需要从已打开的大型数据文件定位变量。两种请求的范围、代价与身份不同，不能让普通文件名查找触发所有文件的科学数据读取。

输入为用户选择的目录/文件名模式或当前文件的变量描述；输出为内存结果表与打开/定位请求。源码位于`src/core/search.*`、`src/views/search_panel.*`、`src/app/browser_search.*`，集成在`app/hdf_explorer.*`；结果不写数据库，源文件只读。

## ⚖️ 备选方案

1. 文件系统与变量一起建立跨文件数据库：可统一检索，但首次读取、失效和数据语义复杂，超过本轮需求。
2. 只过滤已展开的文件树：简单，但漏掉未展开变量，且无法找到尚未打开的文件。
3. 两个入口、独立结果；变量定位复用当前树与元信息：满足已授权最小流程，采用此方案。

## ✅ 决定

- `core/search.*`只负责文件名匹配、目录遍历及描述字段匹配，不依赖QtWidgets、HDF5或netCDF。文件名无扩展名也参与；不读取数据文件内容，不跟随目录符号链接。
- `views/search_panel.*`拥有控件，管理扫描请求、取消和请求代次；文件系统线程具有独立于面板的生命周期，不作为面板的QObject子对象随其删除。工作线程只执行文件系统操作。扫描结果有数量上限，取消/截断明确显示，旧任务不可覆盖新查询。
- `app/browser_search.*`将已经建立的文件树和有界文本元信息转换成值记录。结果条目使用`QPersistentModelIndex`定位，不长期持有ItemData或裸树节点。变量选择始终核对文件上下文及索引有效性。
- NetCDF/HDF5检索所用文本属性在现有GUI建树阶段读取，检索不触发变量数值读取。支持的固定长文本长度不超过4096字节时读取，超限整项略过并附说明；HDF5单元素可变长文本通过库读取、保留最多4096字节并立即归还。H5Aread不提供单次vlen分配限额，库内部临时分配不在此保证范围。GRIB使用已扫描catalog的虚拟变量，保留各自对象身份与真实场数量，不扫描懒加载Messages页。
- 对搜索交互，MainWindow负责组装、当前文件同步和路由到现有打开/图像/表格/属性动作，仍保有原文件树构建与文件所有权。文件关闭前先失效对应结果；搜索模块不接管文件、数据缓冲或分析窗口。
- 普通匹配为不区分大小写的文字包含；文件名含`*`或`?`才按通配符处理；变量精确匹配只用于名称/路径/参数ID。未知元信息保留空/unknown，不补猜测。

### 🔌 范围、结果与身份

| 对象 | 可检查的约定 |
| --- | --- |
| 当前文件 | 文件树当前选中节点所属根；无选中节点时采用最后一个已打开的根；没有根则无上下文。不是活动Image窗口或磁盘上的同名路径 |
| 文件名查询 | 匹配basename，不匹配整条目录路径；空模式匹配全部，默认递归。`*`/`?`触发Qt通配符的完整文件名匹配，如`C7F*`不等于`*C7F*`；不是正则表达式 |
| 变量查询 | 空查询列出当前目录；普通模式查名称、对象路径、long_name/description、standard_name和GRIB参数ID；单位、shape、场数用于展示。精确模式仍不区分大小写，不把同名候选合并为一个 |
| 变量集合 | 遍历已建立的变量树，包含折叠组及原树中的坐标/维度尺度数据集；不把它们过滤成“仅物理场”。GRIB只列Variables，场数表示其源场数量，不等于唯一层次/时次/成员数量 |
| 定位请求 | `BrowserSearch::Entry`保存值描述和`QPersistentModelIndex`；适配器只在GUI调用期间临时访问树/ItemData。主窗执行动作前核对索引有效、模型相同及文件根相同；索引不是跨关闭/重开可复用的永久ID |

读取元信息与查询分开：当前查询只匹配已收集文本，不再次打开每个变量。路径显示用于区分候选，不替代模型与文件根校验。`Image / Table / Properties`仍执行既有格式、shape和选层约束；检索命中不承诺该对象一定可绘图。

### 📏 限额与完整性

- 文件扫描最多返回10000个文件、访问1000000条目录项；保留前20条错误详情及总错误数。到达限额即标记不完整，不承诺已经发现第10001个文件；目录遍历顺序及限额前的候选子集不保证固定。
- 结果在完成/停止后一次显示；扫描期间只有进度。普通文件包括隐藏、无扩展名文件；按当前`symlink_status`实现跳过被识别为符号链接的文件和目录。该规则不等于对Windows所有junction/reparse类型均已验证，也不构成目录沙箱保证。
- 文件记录的大小、修改时间和路径是扫描时信息，不是原子文件系统快照；不监控外部改动，不按内容或硬链接身份去重。打开前重新检查路径存在，并由原打开流程验证格式与错误。
- 变量表最多显示10000条命中，提示缩小查询；该上限**不是**变量目录构建/内存/耗时上限。当前仍在GUI线程构建完整值目录并过滤，规模取决于现有树；若需要超大目录响应保证，应另立后台快照或分页决策。
- 描述缺失、类型不支持或文本被略过/截短时，零命中只表示已收集的描述中未匹配，不表示文件中没有该物理量；名称和路径仍可检索。4096字节限制针对单属性原始文本保留量，不是QString内存或整个树的总预算。

### 🧵 取消、隐藏和销毁

一个面板同时至多一轮文件扫描；运行期间禁止再次启动，Stop等待当前系统调用返回后才允许新查询。代次是迟到结果保护，当前不实现多轮并发或latest排队。隐藏Dock保留结果且不自动停止扫描；销毁则先使代次失效、请求取消、断开回调。工作线程持有自己的查询和结果，不访问QWidget、树、ItemData或科学库。

线程完成后经`finished → deleteLater`清理；面板析构不得delete仍在运行的QThread。此回收依赖所属线程事件循环仍能处理延迟删除，不能由此声称进程退出前必定已析构。不可中断的文件系统调用没有有界停止时延；需要强制超时或退出前确定回收时须重新设计执行边界。Qt线程与持久索引约定见下方依据。

## 📦 后果

查找功能不引入外部grep/rg依赖，也不改变数值读数、选层和比较语义。关闭查找面板不关闭数据；重新打开可继续当前结果。首版不支持内容扫描、跨文件变量索引、中文物理量别名和自动选成员。

扫描遇到不可访问目录、取消或数量上限时必须显示不完整状态。网络文件系统一次系统调用可能阻塞，停止是协作取消；销毁窗口不等待该调用，也不能提前销毁运行线程。

## 🧪 验证与复审

验收范围为合成目录的无扩展名、大小写、通配符、递归、同名不同路径、取消和数量上限；合成NC/HDF及GRIB的描述搜索、精确匹配、折叠树定位和关文件失效；真实C7F样本只读验收。实现入口为`tests/search_test.cpp`，实际运行、失败与通过证据留在SEARCH-001，不把本节清单当作全部已经执行。

2026-11-24补齐并通过4095/4096/4097字节固定/可变长文本、10000条变量展示边界、隐藏面板后扫描及重开文件旧索引失效检查；连同既有重复名称/参数身份、C7F等12个功能槽在Release/Debug通过。证据位于开发日志`logs/PROJ-001/verify-20261124-014939-804293/`。真实ACL拒绝、Windows全部链接类型、长期阻塞网络调用和退出前文件扫描线程回收不属于当前保证，需另立独立夹具；普通本地取消不能证明这些情形。

增加持久化目录、跨文件内容读取、后台变量目录、链接跟随、硬停止要求，或改变文件/线程所有权时复审并另立ADR；文字澄清保留本记录及修订说明。Accepted表示采用决策，不等于实现或验收已完成。
