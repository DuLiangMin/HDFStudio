# 🧩 ADR-0002：先分离表格与启动职责，保持所有权

- 状态：Accepted。
- 日期：2026-11-23。
- 决策依据：本轮已授权源码拆分；以行为保持的可验证增量实施。
- 前置：[ADR-0001](0001-document-authority.md)。

## 🎯 背景

`hdf_explorer.cpp`同时包含main、启动界面、节点载荷、HDF/NetCDF表格模型、层导航和主窗口。表格实现不需要读取主窗口私有成员，但其类定义和辅助读数函数被同一编译单元绑定。文件树与MainWindow仍存在friend访问，适合另定接口逐步处理。

## ⚖️ 备选

1. 仅按行数切分MainWindow成员实现：减小文件，但职责与接口几乎不变。
2. 一次重写为通用会话/插件框架：同时改变生命周期、多个数据后端和UI接口，验证范围过大。
3. 提取已有完整职责，通过小接口连接，保留存量所有权：适合当前工程。

## ✅ 决定

采用方案3：

- `app/main.cpp`只编入产品目标，负责启动与已有preview批处理；共享启动控件在`startup_splash.*`。
- `views/legacy_grid.*`对外只暴露模式和创建函数，内部实现TableModel、ChildWindow及ChildWindowTable。主窗口仅登记/展示返回的QWidget，通过已有LayerNavigation进行导航。
- 共享`ItemData/hdf_dataset_t`移入`app/browser_item.hpp`，是兼容载荷，不冒充格式中立核心DTO。classic缓冲辅助函数放`app/legacy_grid_data.*`。
- 数据缓冲仍由树载荷拥有，模型只借用；关闭顺序仍为视图→树载荷→缓冲。Qt类名、信号、对象名、日期服务、数值文本与文件读取行为保持。
- 表格模块不得包含`hdf_explorer.hpp`或访问MainWindow私有字段；模型/子窗口不暴露给主窗口。core保持不依赖QtWidgets。

## 📦 后果与已知边界

主窗口、产品入口和表格可以分别维护。表格目前仍依赖兼容节点载荷和应用层导航，属于明确记录的过渡边界，并非完成全部分层重构。文件树和格式遍历留在主窗口，暂不修改GRIB调度、数值算法或Raster缓存。

搬移含Q_OBJECT的类型必须保持moc生成与目标注册；Qt 6使用AUTOMOC，cpp内私有类显式包含对应moc输出。Qt类身份与销毁语义不能因隐藏实现而改变。

## 🧪 验证与复审

比较搬移函数正文，确认源目标清单和无反向主窗口依赖；构建两配置产品/相关测试，定向检查表格、导航、日期、关闭及preview入口。通过后停止，不运行无关全量矩阵。

后续若多个格式需要统一表格数据提供者，再提出新ADR替换ItemData借用契约；若文件树继续增加MainWindow私有访问，则单独设计浏览动作接口。不能借本ADR直接启动全面重写。
